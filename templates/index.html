How it works
01

Scan every sample

Each H.264 packet is checked for a valid length-prefixed NAL header, without decoding the video.

02

Find the boundary

The last damaged sample is located, then the first clean keyframe after it with a stable run of valid samples.

03

Cut and verify

The tail is stream-copied. The first output packet must match the source byte-for-byte, then the result is decoded.

Honest limitation: video before the boundary was overwritten in place. It cannot be reconstructed from this file. The app recovers the intact tail and all surviving audio — not the lost frames.
